## Decisions

- Input source is explicit: `clarc --file <path>` reads a file, `clarc --file -` reads stdin. Without `--file` (and without `--agentic-help`) it is an error (non-zero, message on stderr naming `--file`, nothing on stdout). Rejected: keeping stdin as the silent fallback (the point of the change; a bare `clarc` used to hang waiting for a pipe). Piping stays supported: `… | clarc --file -`.
- A diagram is for one provider: `--aws` (default) or `--azure` defines the scope of the whole input. **This supersedes the ul3kp decision "one input renders under both themes with provider-neutral service keys and aliases"**; the neutral keys (`cdn`, `object-storage`, `function`, …) and their aliases are gone.
- A node's `service` is the name of a drawio glyph of the chosen provider, and nothing else (plus `note`, a text box, also the look of a node without a service):
  - aws: the stencil name as drawio calls it (`lambda`, `s3`, `route_53`, `elastic_beanstalk`, `cloudwatch_2`, `role`, …); azure: the icon path `<category>/<Name>` (`compute/Function_Apps`), or the bare `<Name>` when exactly one category has it (an ambiguous bare name is an error listing the candidates).
  - Names compare ignoring case, `-`, `_` and spaces (`route53` = `Route_53`).
  - Typos fail: an unknown glyph is an error that names the node, suggests up to five close names (substring or edit distance ≤ 2) and links to the full list; it is no longer a warning plus a note. An aws name is not an azure glyph and vice versa. Rejected: warning and drawing a blank/default shape (it fails silently in drawio; the input is LLM-authored so strictness helps); neutral aliases (the diagram is not meant to be both).
  - How a glyph is drawn is known from the embedded index, not from the user: aws names are either resource icons (square, category colour) or standalone shapes; azure are the built-in azure2 svg images. Nothing graphic is embedded, only the list of names (aws: name, kind, fill colour; azure: paths) generated by `scripts/gen-glyphs.py` from drawio's own sources (aws from the AWS4 sidebar palettes, minus arrows/groups/illustrations; azure from `img/lib/azure2`, minus the menu icons). Regenerate when drawio's icon set changes.
  - Visible change versus ul3kp: names follow drawio, so `cloudwatch` is now `cloudwatch_2`, and `parameter_store` / `elastic_ip_address` are drawn as the standalone shapes drawio defines (before: as resource icons). Layouts did not change.
- data vs nf belongs to the link, not the node (fargate → s3 is data, fargate → cloudwatch is nf). An edge is data by default; `"kind": "nf"` marks a non-functional link (DNS, monitoring, identity, configuration, image pull). Nodes carry no class. nf edges flow top to bottom and are dashed unless `style` says otherwise; `style` overrides the line. **This supersedes the ul3kp rule "an edge is nf if an end is nf service"**; the fixtures got explicit `kind: nf` on the edges that used to be nf by derivation, so their layouts are unchanged.
- The example was requested as an `example-json` sub-command; it grew into a full guide for LLMs, so it is the flag `clarc --agentic-help` instead (rename decided with the user; rejected: keeping the `example-json` name). It needs no input, honours `--aws`/`--azure` (aws default) for the example and the common glyphs, prints to stdout, exits 0. The output starts with the contents of `--help` (so one call gives an agent the whole interface), then a blank line, then:
  1. a complete valid input for that provider: titled "Web app behind a CDN", with a `description` (the subtitle under the title), one group (a `network` frame "VPC"), 4 nodes (client, cdn, a vm that is a member of the group, dns) using that provider's glyph names, 3 labelled edges (the DNS one `kind: nf`) and a `hints` section of exactly two entries (client `start`, dns `below` the cdn). Renders without warnings;
  2. after a blank line, reference text for an LLM writing its own input: all hint directives (`start leftOf rightOf above below sameRow sameCol`, one-phrase meaning, `<id>` refers to another node, at most one `start`); how `service` names work (rules above) with a short curated list of common glyphs of that provider (about 18, each with what it is used for: client, server, CDN, DNS, bucket, VM, function, containers, managed app platform, API gateway, databases, queue/topic, registry, identity, secrets, monitoring) and links to the full lists of names of both providers, aws and azure, regardless of the theme flag (the full lists are deliberately not printed); the group frame kinds (`network` aka vpc/vnet, `region`, `cloud`, `group` default) with purposes; how edges work (data default, `kind: nf`, `style`).
- Guarded by tests: the example parses, stays within the size limits, contains a group with a member and renders without warnings in each theme; the directive list equals the keys the input accepts (checked against the parser's own list); every common glyph resolves in its theme, is listed with its purpose and the output links to both full lists without dumping them; every group kind has a purpose; the azure text speaks azure names and the aws text aws names; name normalisation, ambiguity, typo suggestions and "aws name is not an azure glyph" have their own tests; the same service can have data and nf edges.
- Group frame kinds stay provider-neutral and are not glyphs: `network` (aliases `vpc`, `vnet`, `virtual-network`), `region`, `cloud`, `group` (default); each theme draws them its own way (aws group icons, azure dashed blue frame). An unknown frame kind stays a warning plus a plain frame (strictness applies to node glyphs, where a typo means a wrong or missing icon).
- The "full list" links point at drawio's own sources on its `dev` branch (aws: the AWS4 sidebar definition, azure: the `azure2` icon folder), since drawio has no stable public name index; they may move, so the curated common list in the guide is the part that must always be right (tests resolve every entry against the embedded index).
- The e2e script pipes with `--file -`.

## Implementation (abstract)

- CLI: the file argument is optional; `-` selects stdin, a path a file, absence is an error; `--agentic-help` skips input reading and prints the `--help` text followed by the guide text for the theme.
- Glyph resolution: embedded name indexes per provider; normalise, look up, classify by index entry; failure builds the suggestion message. Composition takes the theme, resolves every node's glyph (first failure aborts), derives edge kinds only from the edge itself, and the exporter formats the look from the glyph (resource icon, standalone shape or image path).
- The guide text is generated per theme from a parametrised example document, constant tables (directive, group purpose) and the curated common-glyph tables.
